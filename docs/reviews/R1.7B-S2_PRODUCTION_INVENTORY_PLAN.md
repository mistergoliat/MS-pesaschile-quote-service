## B. Bounded scope

In scope: define **what** to inventory, **from which source**, **with which
command**, **under which privilege**, **what output shape is acceptable**, **who
owns it** and **what blocks it**; define F13/F20/F21 decision logic and STOP gates;
define evidence handling and the authorization request.

Out of scope and not authorized by this plan: any production read; isolated
restore or real-data migration rehearsal (R1.7C); provisioning, role, secret,
registry, storage, network or routing change (R1.7B provisioning); deployment or
canary (R1.7D); V1 cutover (R1.7E); migration 000010 or any guard change; R4.

| Class | Meaning | Example |

## E. Evidence capture and redaction contract

### E.1 Output classes

| Class | Where it lives | May contain | Must never contain |

| **Never captured** | Nowhere | — | DB passwords or URLs with userinfo, `SERVICE_AUTH_TOKEN`, `QUOTE_DOCUMENT_REF_SECRET`, bearer tokens, registry `tokenSha256`, Gmail client secret/refresh/access tokens, CA/TLS private keys, `archive_command`, `pg_user_mappings.umoptions`, `pg_subscription.subconninfo`, `/proc/*/environ` raw, `docker inspect` unfiltered, `systemctl cat`, `pm2 env`, `nginx -T` unfiltered |

### E.2 Capture rules

1. Execution is by a **named human operator** holding the credential; credentials come
   from `pg_service.conf` + `.pgpass` (mode 0600) or the secret store's own CLI, never a
   command-line argument, shell history or URL in an environment variable visible to
   other users. Claude or any other assistant never receives credentials or raw output.
2. Every command runs from a reviewed script whose SHA-256 is recorded before execution.
   Scripts are executed exactly as reviewed; any change requires re-review.
3. Raw output goes only to the restricted store (`umask 077`). The operator records
   per command: command ID, script SHA-256, UTC start/end, exit code, host label,
   SHA-256 of the raw output file.
4. The public summary is derived from restricted output by aggregation only, then passes
   the redaction gate (E.3). Only the public summary may be shared in chat or Git.
5. Any S2 HTTP probe sends `User-Agent: r17b-s2-inventory` so it can be excluded from
   consumer aggregation (§I).
6. Accidental exposure of a secret (displayed, logged or written outside the restricted
   store) stops execution immediately and is reported to Security as an incident.
   Rotation is a separate authorized action, not part of S2.
7. Restricted evidence retention/destruction follows the owner's U1 decision; until then
   it is kept, never deleted opportunistically.

### G0. Read-only database session guard

```bash
cd "<RESTRICTED_DIR>" && umask 077
PGOPTIONS='-c default_transaction_read_only=on -c statement_timeout=30s -c lock_timeout=1s -c idle_in_transaction_session_timeout=60s' \
PGAPPNAME=r17b-s2-inventory \
psql "service=<PG_SERVICE>" -X -q -v ON_ERROR_STOP=1 -P pager=off \
     -f r17b-s2-db-inventory.sql -o db-inventory.raw.txt
```

`r17b-s2-db-inventory.sql` is the concatenation of G4–G8 and G14 wrapped as:

```sql
begin transaction isolation level repeatable read read only;
-- G4 ... G8, G14 (in that order; branches use \if on G4.2 markers)
rollback;
```

One repeatable-read snapshot makes all aggregates mutually consistent. `nextval`,
`setval`, DDL and DML fail under `read only`. The only file writes are client-side
`\copy ... to` in G6.6/G7.6 (T4 only), into the restricted directory.

### G10. Ledger hashing and orphan comparison (T4)

```bash
# G10.1 r17b-s2-verify-ledger.sh <root> <ledger.tsv> <out.tsv>   (reviewed; read-only)
#!/usr/bin/env bash
set -euo pipefail; umask 077
root="$(realpath -e -- "$1")"; ledger="$2"; out="$3"
[ -e "$out" ] && { echo "refusing to overwrite $out" >&2; exit 64; }
[ "$(find "$root" -xdev -type l | wc -l)" -eq 0 ] || { echo "symlinks present: STOP" >&2; exit 65; }
re='^[A-Za-z0-9._/-]+$'
while IFS=$'\t' read -r id key sha len; do
  status=OK; size=-
  if [[ ! $key =~ $re || $key == *..* || ${#key} -gt 500 ]]; then status=KEY_INVALID
  else
    f="$root/$key"
    if   [ -L "$f" ]; then status=SYMLINK
    elif [ ! -e "$f" ]; then status=MISSING
    elif [ ! -f "$f" ]; then status=NOT_REGULAR
    else
      size=$(stat -c %s -- "$f")
      if [ "$(sha256sum -- "$f" | cut -d' ' -f1)" != "$sha" ]; then status=HASH_MISMATCH
      elif [ "$len" != '\N' ] && [ "$len" != "$size" ]; then status=LENGTH_MISMATCH; fi
    fi
  fi
  printf '%s\t%s\t%s\n' "$id" "$status" "$size" >> "$out"
done < "$ledger"
cut -f2 "$out" | sort | uniq -c                 # public aggregate
```

```awk
# r17b-s2-config-shape.awk — input KEY=VALUE lines; prints a value only for allowlisted,
# non-secret keys with a conservative value shape. Everything else: present/empty only.
BEGIN {
  allow = "^(NODE_ENV|HOST|PORT|LOG_LEVEL|HTTP_[A-Z_]+|APP_SHUTDOWN_TIMEOUT_MS|DATABASE_SSL_MODE|DB_POOL_[A-Z_]+|DB_QUERY_TIMEOUT_MS|SERVICE_NAME|SERVICE_VERSION|HEALTHCHECK_DATABASE_TIMEOUT_MS|HEALTH_PROBE_[A-Z_]+|QUOTE_ISSUANCE_[A-Z_]+|QUOTE_EXPIRY_INTERVAL_MS|QUOTE_INTEGRITY_CHECK_INTERVAL_MS|QUOTE_EMAIL_PROVIDER|QUOTE_EMAIL_[A-Z_]+_MS|QUOTE_EMAIL_DELIVERY_[A-Z_]+|QUOTE_EXPIRATION_[A-Z_]+|QUOTE_DOCUMENT_CLEANUP_[A-Z_]+|QUOTE_DOCUMENT_ORPHAN_MIN_AGE_MS|QUOTE_RENDER_VERSION|NODE_VERSION|TZ|LANG)$"
}
/^[[:space:]]*#/ { next }
{
  line = $0; sub(/^export[[:space:]]+/, "", line)
  i = index(line, "="); if (i == 0) next
  k = substr(line, 1, i - 1); v = substr(line, i + 1)
  if (k !~ /^[A-Z][A-Z0-9_]*$/) next
  if (k ~ allow && length(v) <= 64 && v ~ /^[A-Za-z0-9._:\/+-]*$/) { print k "\tvalue=" v; next }
  if (k == "DATABASE_URL" || k == "MIGRATION_DATABASE_URL") {
    h = v; sub(/^[A-Za-z]+:\/\/([^@\/]*@)?/, "", h)
    if (substr(h, 1, 1) == "[") h = substr(h, 1, index(h, "]")); else sub(/[:\/?].*$/, "", h)
    c = (h ~ /^(localhost|127\.0\.0\.1|\[::1\])$/) ? "loopback" \
      : (h ~ /^(10\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[01])\.)/) ? "ipv4-private" \
      : (h ~ /^[0-9.]+$/) ? "ipv4-other" : (h ~ /^\[/) ? "ipv6" : "dns-name"
    print k "\tpresent host_class=" c " query_params=" (index(v, "?") ? "yes" : "no"); next
  }
  print k "\t" (length(v) ? "present" : "empty")
}
```

## H. F13 — legacy artifact decision tree and STOP criteria

Inputs: INV-04/05 (schema kind), INV-09 (G8, G10), INV-08 (G9.3), INV-10 (G11),
INV-12 (V1 cleanup flag). Frozen requirement: `QUOTE_V2_V1_MIGRATION.md` §1.1,
row `issued_pdf_storage_key`: *"file moved/copied to the content-addressed layout;
bytes unchanged; hash verified; missing file → migration exception"*.

```text
Every authoritative source inventoried? (live DB, live root, every DB backup, every artifact copy)
 ├─ no ───────────────────────────────────────────── UNDETERMINED: F13 stays open; no outcome is claimed
 └─ yes
     ├─ any MISSING / HASH_MISMATCH / LENGTH_MISMATCH / KEY_INVALID / SYMLINK / NOT_REGULAR ── D: STOP
     ├─ any PDF/HTML file or backup PDF without a DB manifest, or manifests without a DB ───── E: STOP
     ├─ committed legacy PDFs = 0 everywhere and 0 legacy files anywhere ────────────────── A
     ├─ all committed legacy keys canonical (G8 key_canonical = committed) and all verify OK ─ B
     └─ any committed legacy key not canonical ──────────────────────────────────────────── C: STOP
```

D and E take precedence over B/C: an integrity question is resolved before any
relocation question.

| Outcome | Proof required | Disposition |
|---|---|---|
| **A** — no legacy issued PDFs | Live DB `committed_quotes = 0` (or no DB, with absence attested by DBA); root has 0 files under `quotes/` and 0 legacy PDFs; every DB backup shows no quote rows (G11.4) or is evaluated in R1.7C; every artifact copy has 0 PDFs. A quiet or unreachable DB alone is not proof (C13) | Relocation **N/A, subject to proof**; record evidence references; re-check at final paired capture |
| **B** — legacy keys already canonical | Per-row equality `k = artifacts/sha256/<aa>/<bb>/<sha>.pdf` for every committed row, verified bytes for every row, explanation of provenance (C1 says V1 never wrote this form) | No relocation; record why the deployed V1 differs from `fade75d` |
| **C** — noncanonical keys | Count by key form (`key_v1_layout`, `key_other`, `key_violates_v2_check`); restricted list of affected quote/document ids; verified bytes | **STOP.** See below |
| **D** — missing/mismatched bytes | Restricted per-row status ledger; V1 cleanup flag/history; backup candidates | **STOP: integrity incident.** Preserve all bytes and evidence; locate hash-identical backup bytes; never regenerate V1; no migration planning proceeds |
| **E** — orphans | Counts of files without manifests and manifests without files; backup-only PDFs | **STOP.** Possible DB loss, V1 cleanup residue or out-of-band copies; data owner reconciles source truth before any outcome is chosen |

**C — required STOP record** (no design is produced in S2):

1. Exact affected manifests: count per key form; restricted ledger of quote/document
   ids with key form and verification status.
2. Frozen requirement: `QUOTE_V2_V1_MIGRATION.md` §1.1 (above).
3. Blocker: 000007 preserves the V1 key and asserts it in its post-conditions;
   `quote_documents_guard` rejects any `storage_key` change; runtime has no UPDATE on
   `quote_documents`; no relocation tool exists (pre-flight N).
4. Whether 000010 is actually required — it depends on an owner decision among options
   that are listed here **only to frame that decision**, none recommended or designed:
   - (i) a formal contract amendment accepting preserved legacy keys permanently
     (runtime already serves verified legacy keys by hash): no 000010, but a change to a
     frozen document;
   - (ii) relocation **before** conversion, on the V1 schema (copy verified bytes, change
     V1 `issued_pdf_storage_key`, which has no immutability guard): no 000010, but a
     production data change on the V1 source of truth, affecting the running V1;
   - (iii) relocation **after** conversion through a new migration (potential 000010)
     that changes guarded manifests under the owner role: requires a guard strategy.
5. Additional STOP if `key_violates_v2_check > 0`: 000007 itself would fail with a
   constraint violation rather than a report; this needs a data decision before any
   migration attempt.

Never draft 000010, alter or disable guards, edit 000007, or copy files as an
"inventory step". Copying alone never relocates the authoritative manifest.

## I. F20 — V1 consumer inventory methodology

### I.1 Principle

Absence of traffic in a window is not absence of consumers. Closure requires
**independent sources plus owner attestation**, over a business-approved window that
covers every known periodic cycle (e.g., month-end, quarter-end, seasonal campaigns).
This plan does not set a numeric window; the business owner approves one (U-10).

### I.2 Consumer classes to cover

| Class | Why it matters | Primary sources |
|---|---|---|
| Interactive/API callers of `/v1/quotes*` | Will receive 410 at cutover | Proxy logs (G12.3), app logs (G12.4), DB `source_system`/`actor_type` (G6.5), attestation |
| Batch/scheduled callers (cron, CI jobs, workflow tools) | Infrequent; easily missed by short windows | Host crontabs/timers (G12.5), CI/automation configs (owner-provided), DB creation-time histograms (G6.2), attestation |
| Holders of `/v1/documents/doc_*` links | References never expire (C7); may be embedded in CRM records, emails, chat | Proxy/app logs for `/:documentRef`, attestation from teams that shared links |
| Holders of `SERVICE_AUTH_TOKEN` | Upper bound of authenticated V1 callers (C6) | Secret-store access metadata (names of systems with read access), attestation |
| Direct database consumers | `000007` drops V1 tables; dependent views/FKs/publications would abort it or break readers | G4.6 dependents, G4.7 sessions by role/application, G14 grants to non-service roles |
| In-process V1 jobs | Expiration scheduler, orphan cleanup, Gmail worker stop at cutover; pending V1 deliveries become `failed`/`unknown` by 000007 | G15 flags, G6.3 delivery/outbox states, G16.2 |
| Monitoring/health checkers | Not V1 business callers, but must be re-pointed (`/health` differs) | Proxy logs for `/health*`, monitoring config attestation |
| R4 / sales integration | Known integration; R4 not accessed here | R4 owner attestation of base URL, routes, schedule; no R4 repository read |

### I.3 Procedure

1. Establish the evidence window per source: oldest log entry (G12.1), DB lifetime
   (`min(created_at)` from G6.2/G6.5), stats reset time (G4.7).
2. Aggregate `/v1` traffic by day, method, normalized route, status, client (restricted)
   from proxy and app logs, excluding the S2 user agent.
3. Aggregate DB-side attribution over the database lifetime (G6.5) — this covers periods
   older than log retention.
4. Sample DB sessions (G4.7) at least at the start and end of execution; record that a
   point-in-time sample has low confidence by itself.
5. Map clients → candidate callers using network ownership, hostnames, user agents,
   `source_system`, and secret-store access lists. Each mapped client receives a
   pseudonymous label for the public report.
6. Send each candidate owner the register row for attestation (owner, purpose, routes,
   schedule, last use, V2 readiness, cutover acknowledgment).
7. Ask every integration owner listed in AC/AA of the pre-flight for an explicit
   "we do / do not call Quote V1" statement, including unknown-to-us callers they host.
8. Record residual unknown clients as **open** with their traffic profile; they block E.

### I.4 Confidence

| Level | Requirement |
|---|---|
| High | ≥2 independent technical sources over the approved window **and** owner attestation |
| Medium | One technical source over the approved window and attestation, or two technical sources without attestation |
| Low | Single source, partial window, or inference only |
| Open | Observed traffic or token holder with no identified owner |

"Zero consumers" may be recorded only when: logs cover the full approved window with
no `/v1` business traffic, DB attribution shows no activity in that window, no
dependents/foreign sessions exist, all token holders and integration owners attest
non-use, and no open rows remain. Otherwise the result is "no consumers observed, not
closed".

| Field | Content |
|---|---|
| `callerLabel` | Pseudonymous stable label (mapping restricted) |
| `class` | One of I.2 |
| `owner` | Named role/team |
| `interfaces` | Normalized V1 routes or DB objects |

## J. F21 — rollback compatibility and STOP gates

### J.1 Compatibility matrix (image × schema/root)

Root V1 = files under `quotes/`; root V2 = same files at preserved keys plus
`artifacts/sha256` and `artifacts/tmp`. V2 never moves or deletes legacy files.

| Image ↓ / State → | V1 schema (000001–000005) + V1 root | V2 schema (000009) + V2 root |
|---|---|---|
| **V1 build** (exact deployed identity: INV-01, unknown) | Status quo; only valid pairing for V1 | **Prohibited.** V1 tables are dropped by 000007; no shim; never proposed |
| V2 build < `26e7307` (pre-S1) | Unready (`SCHEMA_BEHIND`); `/v1` → 410 | Not a target: rejects `verify-full`/CA transport config (C12) |
| V2 `26e7307`…< `e094fad` (S1, pre-R1.7A) | Unready; `/v1` → 410 | Schema-compatible but lacks issuer `pesaschile-cl-v2`/template v5: v2-profile issuance fails closed, v5 repair impossible. Not a target |
| V2 `6735352` (current candidate lineage) | Unready; `/v1` → 410 → outage for V1 callers; must never be routed | Target pairing |
| Future V2 release | Same as above | Rollback target only if J.2 C1–C6 hold |

A V2 image facing a V1 schema stays not ready and its jobs do not run (persistence
gate), so it causes no DB mutation — but any routing to it retires V1 for that traffic.

### J.2 Criteria for a V2 rollback image

- **C1** Identical migration manifest (names and checksums) to the DB's applied set.
- **C2** Knows every `issuer_profile_id` and template on non-terminal operations (G7.3)
  and, for repair, on manifests it may need to reproduce.
- **C3** Same renderer profile (Node `24.14.0`, pinned zlib, fonts); the renderer refuses
  other runtimes.
- **C4** Accepts the deployed configuration (transport mode/CA, registry format, env schema).
- **C5** Same delivery envelope/provider semantics, or provider disabled.
- **C6** Proven on an isolated clone of the current DB/root (R1.7C/D evidence).

### J.3 Phases and permitted recovery

| Phase | State | Permitted recovery | Never |
|---|---|---|---|
| P0 | V1 live, no conversion | Nothing to roll back | — |
| P1 | V1 quiesced, final paired capture taken | Unquiesce V1 | Use a pre-quiescence snapshot as final boundary |
| P2 | DB converted (000007–000009), **no V2 process started** | Pre-V2-mutation rollback: restore final paired V1 capture (or keep an untouched V1 DB if conversion ran on a restored copy), restart V1 image, re-route | V2 process start "to check"; `down` migrations |
| P3 | V2 process started, no business traffic | **Post-mutation by default**: expiry materialization (G6.2 prediction) and sweeps may have written audit/state. Discarding them requires an explicit owner decision with a ledger of every discarded transition | Silent discard |
| P4 | V2 accepted business mutations (drafts, issues, numbers, bindings, manifests) | Roll-forward on the same schema: fix in a V2 release meeting C1–C6, or operator procedures already defined; DB/root restores only into isolated targets for analysis or exact-byte artifact recovery | V1 binary; restoring an older DB/root over live V2; trigger bypass; export-to-V1 |
| P5 | Email enabled and sends occurred | As P4; provider disabled on recovery; `sending` never replayed; `unknown` preserved | Resend, reopening restored `sending` rows |

### J.4 STOP gates

| Gate | Condition that stops cutover planning |
|---|---|
| R-1 | Deployed V1 build/image identity not established (INV-01): no defined V1 return target |
| R-2 | No verified paired DB + root backup restorable in isolation (F14) |
| R-3 | V1 producers (external callers, scheduler, cleanup, Gmail worker, operators) not all inventoried and quiescible (F20, C5) |
| R-4 | Owner has not signed the "point of no V1 return" at the first V2 process start (C11) |
| R-5 | Predicted boot mutations (G6.2/G7.2 expiry backlog, pending deliveries) unknown or unapproved |
| R-6 | No V2 image meets C1–C6 and the owner has not explicitly accepted roll-forward-only recovery |
| R-7 | Any F13 outcome C/D/E or UNDETERMINED unresolved |
| R-8 | Email enablement without the separate W10 gate |

**Recommendation:** treat P3 onward as roll-forward only. Evaluate, as an owner
decision for R1.7C/D, converting a **restored copy** of the final V1 capture into a
new database and a copy of the root, leaving the original V1 DB/root untouched and
read-only until the owner closes the rollback window. This keeps P2 rollback lossless
without any downgrade. It is a recommendation to evaluate, not an authorized design.
