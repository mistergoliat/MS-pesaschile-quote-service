## X. Infrastructure limitations, blockers and options without EBS

There are no blockers for R4-J3 integration testing. Limitations:

1. **Disk headroom is 1,064 MB (90 %).** That is enough to run, but the **next image release** cannot be loaded the same way. Loading this one cost a measured 1,213 MB peak. Options that don't involve EBS:
   - **(a)** Remove the previous Quote image only after the new one is verified. This still needs about 1.2 GB free at load time, so it isn't enough on its own.
   - **(b)** Reduce the image size through a reviewed Dockerfile change (outside this slice): drop dev dependencies from the runtime stage (`node_modules` 294 → about 50 MB) and avoid the `chown -R` duplicate layer (308 MB). Measured inputs suggest about 0.25 GB installed and about 0.35 GB peak.
   - **(c)** Owner-authorized removal of the dormant V1 container and volume (49 MB).
   - **(d)** Owner decision on the `ec2-user` npm cache (563 MB) and journal/log retention (383 MB). These are shared tooling, so they are not touched here.
2. **No swap and 3.8 GB RAM.** Quote V2 uses about 105 MB combined, with caps of 768 MB.
3. **Single instance, no backups** for `quote-v2-integration-pgdata` and `-documents`. Acceptable for integration; required before any real use.
4. `restart: on-failure:5` does not restart the app after a host reboot. Run `docker compose -p quote-v2-integration up -d` after a reboot. Postgres is `unless-stopped`.
5. The dormant V1 compose maps Postgres to `0.0.0.0:5432`. It is exited and unchanged, but must not be restarted as-is.
6. The CRM worker stop (§B) is an open operational issue for the owner.

`provision-secrets.sh` findings:

- **Safe:**
  - `set -euo pipefail` and `umask 077`; the directory is 0700.
  - Randomness from `openssl rand -hex 32` (256-bit).
  - Passwords and tokens reach files via builtins and redirection, never argv. No value is printed; the last line lists file names only.
  - **Fail-closed, not idempotent:** it refuses to run if the directory exists.
  - `sudo -n` failures abort.
  - The CA key is shredded after `openssl verify` succeeds.
- **Low-risk observations (not changed, so the committed script stays the one executed):**
  - (1) The two token **hashes** are passed to `jq --arg`, so they are briefly in argv, visible to same-user/root processes on the host. Hashes are not credentials. A future revision could use `--rawfile`.
  - (2) The raw-token JSON intermediates are shredded on success. If the script fails mid-way they remain inside the 0700 directory, and the refusal-on-exists forces manual inspection.
  - (3) `openssl` stderr is suppressed; errors still abort via exit status.
